## 🔵 Fundamentals

---

### Q1. What is Server-Side Rendering (SSR) in Angular?

**Answer:**
SSR renders Angular applications into static HTML on the server in response to a client request. The browser receives pre-rendered HTML first, followed by downloading the client JS bundle to make the page interactive (Hydration).

Benefits:
- **Faster First Contentful Paint (FCP)**.
- **Improved SEO**: Search engine crawlers receive fully rendered HTML pages.
- **Better Social Media Previews**: Open Graph tags and meta tags are populated on the server.

---

### Q2. What is Non-Destructive Hydration (Angular 16+)?

**Answer:**
Before Angular 16 (legacy Universal), hydration was **destructive** — Angular destroyed the server-rendered DOM nodes and recreated them from scratch on the client, causing a noticeable UI flicker.

**Non-Destructive Hydration (Angular 16+)**:
- Preserves the existing DOM nodes generated by the server.
- Traverses the DOM and attaches event listeners / signal bindings to the existing nodes without destroying them.
- Eliminates UI flickers completely.

```typescript
// main.ts (Configuring Hydration)
import { provideClientHydration, withEventReplay } from '@angular/platform-browser';

bootstrapApplication(AppComponent, {
  providers: [
    provideRouter(routes),
    provideClientHydration(withEventReplay()) // Event Replay (Angular 18+)
  ]
});
```

## 🟡 Advanced SSR Features

---

### Q3. What is Event Replay (`withEventReplay`) in Angular 18+?

**Answer:**
When a user interacts with a server-rendered page before the JavaScript bundle finishes downloading and hydrating (e.g., clicks a button), traditional apps drop the event.

**Event Replay** captures user interactions (clicks, inputs) during the unhydrated window using an inline script and automatically **replays those events** once hydration completes.

---

### Q4. What is Server-Route Configuration (`provideServerRouting` / Prerendering) in Angular 19+?

**Answer:**
Angular 19 introduced explicit per-route SSR rendering modes:

```typescript
// app.routes.server.ts
import { ServerRoute, RenderMode } from '@angular/ssr';

export const serverRoutes: ServerRoute[] = [
  // Static Page -> Prerendered at build time (SSG)
  { path: 'about', renderMode: RenderMode.Prerender },

  // Dynamic Route -> Server Rendered on demand (SSR)
  { path: 'user/:id', renderMode: RenderMode.Server },

  // Interactive Dashboard -> Client Side Only (CSR)
  { path: 'dashboard', renderMode: RenderMode.Client }
];
```

## 📝 Quick Reference

```
SSR Hydration Flow:
1. Server renders HTML string ──> Sends HTML to Browser (FCP Instant)
2. Browser downloads JS Bundle
3. Angular Client Hydrates existing DOM nodes (Attaches Signal/Event Bindings)
4. Event Replay replays any clicks user made during hydration window!
```
